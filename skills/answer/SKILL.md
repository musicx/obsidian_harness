# 回答问题

**完成的标准：** 用户的问题得到了直接的回答，或者得到了"记录里没有"的明确答复和你查过哪里；答案里每个论断都带出处链接。

**边界：** 只读。答案短就只写在 `_report.md` 里；需要成文时才写到 `outputs/`（或该项目的 `reports/`）。不修改任何知识页或项目记录。

## 步骤

1. 读线程页，确定用户到底在问什么。问题有两种合理的理解时，按更可能的那种回答，并在答案开头说明你的理解。
2. 找依据，**两条路都要走**：
   - 目录：读 `_context/candidates.md`（引擎按问题找出的相关页面），打开最相关的几页；沿页面里的链接再读两三跳。关于项目的问题读 `projects/<项目>/status.md` 和 `log.md`。
   - 全文：用 grep 在 `wiki/`、`practice/`（以及该项目目录）里搜问题的关键词、同义词和英文名。
   - 一般读 5 到 8 页就够。只有两条路都没找到，才能说"没有记录"。
3. 在 `_scratch/claims.md` 里列出答案要用到的每个论断和它的出处（这个文件不会被保存）。分三类：记录里明确写了的；从记录推出来的（标"推断"）；记录之间互相矛盾的。记录里没有的不写进答案。
4. 按问题类型组织答案：

   | 问题类型 | 形式 |
   |---|---|
   | 是什么、是多少、是谁 | 一两句直接回答 |
   | A 和 B 的区别 | 对比表 |
   | 怎么做 | 步骤 |
   | 我们对 X 了解多少 | 要点小结，加"尚不清楚的地方" |
   | 现在什么情况（项目） | 结论，加当前 blocker 和待决事项 |

5. 决定放哪里：
   - 几句话能说清：直接写进 `_report.md` 的摘要。
   - 需要表格、步骤或超过 300 字：存为 `outputs/YYYY-MM-DD <问题的简短标题>.md`（项目问题存到 `projects/<项目>/reports/`），`_report.md` 里写结论和文件链接。
6. 对照 `_skills/plain-writing/SKILL.md` 自查。

## 答案页格式

    ---
    type: answer
    question: 用户的问题
    date: YYYY-MM-DD
    sources: ["[[依据的页面]]"]
    ---
    # <问题>

    直接回答。

    ## 依据
    ## 记录里没有或有分歧的地方

出处写法：知识页 `（[[页面名]]）`，其他位置用完整路径 `（[[projects/<项目>/status|现状]]）`。

## 检查清单

- [ ] 第一句就在回答问题
- [ ] 每个论断有出处；推断标了"（推断）"
- [ ] 记录有矛盾的地方并列写出，没有自己选边
- [ ] 没有任何内容来自记录之外
- [ ] 说"没有记录"之前，目录和全文都查过，并写明了查过什么

## 容易出错的地方

| 发生过的事 | 规则 |
|---|---|
| 知识库只有一句话提到这个概念，答案却写了三段教科书内容 | 库里有多少答多少，然后说明"知识库目前只有这些"，可以建议用户收录更多材料 |
| 问上线日期，只答了一个日期，没提还有一处未裁决的不一致 | 关于项目的问题，先看现状页的"待裁决的不一致" |
| 只查了目录就说没有 | 再 grep 一遍，含同义词和英文名 |

## 报告

`_report.md` 的摘要就是答案本身（或长答案的结论加文件链接），不超过 300 字，用普通段落，带出处链接。知识库里没有时写："知识库 / 项目记录里没有关于……的内容。查过：……"。
