# 写给人读的文章

读者没有参与过程，只读这一篇。这份规程要保证两件事：他用最少的力气拿到他要的东西；他读得出这是一个了解情况、有判断的人写的。

**完成的标准：**

- 主线能用一句话说出来，标题、开头和结尾说的是同一件事。
- 读者只读开头就拿到最重要的东西；长文允许从场景写起，但判断要在开头这一部分出现。
- 每一节都带着读者猜不到的东西：一个事实、一个数字、一段经历或一个判断。
- 事实、数字、名字、引文、链接与素材逐项一致，没有素材之外的经历、细节和出处。
- 自然的句子没有被改动；改别人的成稿时，每处删改都说得出原文哪里绊了读者。

**边界：**

- 判断、经历、情绪属于作者。可以提候选，不能替他定，更不能编。
- 改别人的成稿，默认只动病句、错字和明显的机器腔；删节、合并、调顺序先提议。
- 不评价一篇文章是不是 AI 写的。
- 只管文字。排版发布、配图制作、逐句翻译不在这里。

## 动笔前先读哪一份

按语言和体裁各读一份，不要全读。

| 情况 | 读 |
|---|---|
| 汇报、周报、方案、调研与技术报告、复盘、请示 | `references/report.md` |
| 概念页、操作指南、教程、参考手册、设计说明、README | `references/knowledge-doc.md` |
| 技术公众号长文、博客、经验分享、观点文 | `references/longform.md` |
| 成稿是中文 | 第 6 步时读 `references/zh.md` |
| 成稿是英文 | 第 6 步时读 `references/en.md` |
| 作者有风格说明（`practice/写作风格.md`）或给了样文 | 最先读。它优先于这里的一切默认做法，事实纪律除外 |

语言参考在起草之后再读。起草时满脑子禁忌，写出来的东西只会规矩，不会有内容。

## 被别的操作规程引用时

任务书的"共用规范"里列着这一份时，主规程（`_skill/SKILL.md`）定的步骤、格式、存放位置和出处写法优先，这里的第 1 到 5 步由它的步骤代替。照做的是第 6 步的三遍自查、"结构层的机器腔"和"事实纪律"。体裁参考读主规程指定的那一份，语言参考按成稿的语言读，都在 `_skills/writing/references/` 下。有两处和下文不同：记录里缺的事实按主规程的要求明说"没有记录"，`[待填]` 只留给要作者自己定的内容（答复期限、承诺、请求）；交付说明写进 `_report.md`，不写进成稿。

## 步骤

1. **定读者和目的。** 谁读，他已经知道什么，读完要他做什么或带走什么。没有指定时，写给一个聪明、愿意读、但没有你这些上下文的人。
2. **写出一句话主线。** 只能让读者记住一句话时，是哪一句。它是一个判断，不是一个话题："缓存方案调研"是话题，"缓存该换集群，因为单机每季度宕一次"是判断。写不出来，说明材料还没消化，不要靠动笔来想清楚。素材支持几个不同的主线时，列出候选交给作者选；无法询问时，取素材里作者自己说得最重、依据最足的那个，并在交付说明里写明。
3. **清点素材，由素材定篇幅。** 列出手里真正有的：事实、数字、亲历、原话、可核实的出处。类别名不算，同一个意思的第二种说法不算，读者本来就猜得到的常识不算。每一节至少对得上一件；对不上的节删掉，或者把文章写短。素材不够时，能问就一次问完，不超过三个问题；不能问就写短的，把缺口写进交付说明。不为凑篇幅补例子。素材比成稿多才是常态，写作是把多的材料压成少的文字，不是把少的材料扩成多的文字。向作者要素材时，要他的口述和随手记的原话，啰嗦也行，不要他整理过的提纲。
4. **按体裁搭骨架。** 读对应的体裁参考，列出每一节要回答读者的哪个问题、用哪件素材回答。
5. **起草，只管内容。** 像当面讲给那个读者听一样写。这一遍不想"怎么去机器腔"，只想他读完能带走什么。代作者署名写时，他自己写下的材料就是他的话，直接说；正文里不出现"据设计文档""素材里提到"，素材的来路和缺口写进交付说明。
6. **改稿，三遍分开做，顺序不能反。**
   - **结构。** 用读者的眼睛逐段走一遍，标出三种地方：要靠没写出来的前提才能跟上的（补一句）；偏离主线又没带回东西的（删或移）；要回头重读才懂的（把被依赖的内容提前，论断放在限定条件之前）。然后查下面"结构层的机器腔"。结构有问题时不要用润色去补，一句话别扭，往往是它在同时干两件事，或上一句没把读者带到这里。
   - **句子。** 读语言参考，认出毛病再改，自然的句子不动。
   - **事实。** 对照素材逐项核对数字、日期、版本、名字、引文和链接；检查改写有没有悄悄改掉限定条件和确定程度。
7. **冷读。** 只读标题、开头和各节首句，看能不能复述全文。重要的稿子再找一个没有上下文的读者（没看过材料的人，或一个只拿到成稿的模型），让他回答读者最可能问的三个问题。答不出、答错的地方回去补。
8. **交付。** 用户指定的篇幅、结构和受众是硬约束，交稿前数一遍字数，超了就按体裁参考里的保留顺序删。默认只交正文。改别人的成稿时附上逐处改动。正文里有 `[待填]`、主线是代选的、或替作者下了素材里没有明说的判断时，必须在正文之后附一段交付说明，写明哪里缺素材、哪里未核实、哪些是代选的。

## 结构层的机器腔

词句干净的稿子仍然像生成的，原因多半在这里。它们靠改词去不掉，要回到素材和主线去改，所以放在句子之前查。

| 现象 | 改法 |
|---|---|
| 素材里没有的动机、心理、场景、因果，被补出来让故事更完整 | 删掉，或标明是推断。说得通不等于有出处 |
| 确定程度被抬高：观察写成了意图，可能写成了机制，一次试验写成了普遍结论 | 恢复素材原本的把握 |
| 一个原因解释了所有例子，每个例子都支持论点，没有例外 | 把"发生了什么"和"我认为这说明什么"分开；例子不一致时让它们不一致 |
| 每一节一样长、一样的内部结构，要点正好凑成三条或五条 | 按实际的发现顺序或证据轻重重排，有几条写几条 |
| 文章在评论自己：给证据打分、预告下文、替引语定性 | 删掉，或换成它评论的那个东西 |
| 一句话搬到别的文章里照样成立 | 接回到具体的人、物、选择或后果上；接不回去就删 |
| 由一个人的经历直接推到"你""我们"都如何 | 证据是个人的，就一直用"我" |
| 结尾复述、升华、把每个伏笔都圆回来 | 停在一个具体的决定、代价、后果或没解决的问题上 |

## 几条贯穿始终的判断

- **人味是放进去的，不是删出来的。** 它来自具体的观察、取舍、代价和没想明白的地方。删掉套话只能让文章不讨厌，不能让它有内容。
- **补事实，不换词。** 机器腔的根子是信息密度不够，语言只好靠修辞撑场面。把"赋能"换成"帮助"，仍然是一句空话。
- **不矫枉过正。** 目标是一个认真的人会写出来的样子，不是机器腔的反面。不为了"像人"加口语词、加情绪、加不通顺的句子。
- **证据几成，话说几成。** 承载证据强度的限定词（"据作者自述""未读原文""截至 2026-11"）必须保留；每句都挂"可能""或许"则是作者从文章里消失了。
- **格式跟着内容。** 推理写成段落，并列的事项和步骤才用列表，多个对象多个属性才用表格。
- **改到位就停。** 更短、更克制不是改好的证明，不为了简短删掉原因、条件和边界。句子那一遍只做一轮，反复打磨只会一遍比一遍讲究，一遍比一遍没有人味。读着还是不对时，问题在素材和主线，回到第 2、3 步。

## 事实纪律

与好读冲突时，以这一节为准。

1. 数字、日期、版本号、名称原样保留：不四舍五入，不换单位，不改口径。中英转换时重算万、亿与 thousand、million、billion。自己从素材里数出来、算出来的数（条数、天数、百分比），交稿前重数重算一遍。
2. 链接绑定在它原本支撑的那句话上，不新增素材里没有的链接。
3. 不编造数字、引文、经历、对话、人名和因果。相关不写成因果，计划不写成已完成。
4. 没读到原文的，只引用标题或摘要里有的内容，并就近注明"未读原文"或"转述自某处"。
5. 谁说的还是谁说的；原有的限定（"自述""据报道""目标于某日发布"）保留。
6. 素材里缺一个必需的数或名字时，留 `[待填：……]`，不代填。
7. 拿不准一处修改会不会改变意思，就不改，在交付说明里列出。

## 容易出错的地方

| 发生过的事 | 规则 |
|---|---|
| 开头一段塞进 11 条新闻和 9 个分数，分了三条线却没有主线 | 先写出一句主线，开头只为它服务，其余下沉或删掉 |
| 同一批内容在"编辑说""Top 3""白话简报"里讲了三遍 | 一个意思只在一处展开，别处一句话指过去 |
| 20 条内容每条都套"信号、白话、关键判断、反向视角"四个标签，"反向视角"大多是通用免责 | 不给每条套同一个模板；有针对这一条的真实风险才写 |
| "白话："后面只是把上一句换个说法 | 白话用来解释术语，不用来复述 |
| 抓取失败、限流这些过程信息占了开头 | 过程进文末；影响结论可信度的缺口，在那句话旁边就近说明 |
| 项目状态是黄色，汇报读起来一切顺利 | 结论句直接写出状态和原因 |
| 要求压缩到一页，结果删掉了需要决策的事项 | 压缩时先保决策事项和风险，再保结论依据，最后才是进展细节 |
| 为了显得完整，补了一段读者已经知道的背景 | 背景一句话带过，或给链接 |
| 提交历史有 24 条，成稿写成"23 次提交" | 自己数出来的数，交稿前重数一遍 |
| 要求 600 到 900 字，交出来一千多字 | 指定的篇幅是硬约束，交稿前数字数 |
| 代作者用第一人称写长文，正文里出现"设计文档里记着""下面讲的都以设计文档为据" | 作者自己的材料就是他的话，直接说；来路写进交付说明 |
| 素材里没有的承诺和估计被写进了正文（"搭建约半天""我全程待命"） | 作者没答应的事不替他答应，没有的数留 `[待填]` |

## 把作者的修改留下来

作者手改过一篇稿子之后，把交出去的版本和他改后的版本放在一起，归纳他改了什么、为什么，写进 `practice/写作风格.md`（没有写入权限时，写进交付说明，请作者自己加）。那里放三样东西：作者亲手写的样文；他把初稿改成了什么（改前改后对照）；他不写什么。不放模型对他风格的概括，那只是模型以为的他。样文隔几个月换新的，否则只能写成几个月前的他。这份规程和它的参考文件只收对所有作者都成立的规则。新教训并进已有的条目，不靠加禁用词解决，文件不能只增不减。
