# 中文：句子层面的毛病与改法

改中文稿、或中文初稿写完后的第二遍，读这一份。它是认毛病用的例子库，不是从头套到尾的清单。

三条用法，优先于下面任何一条具体规则：

- **自然的句子不动。** 改过头和没改到位一样算失败。三处改在要害上，好过三十处机械替换。
- **看动作，不看字面。** 每一类毛病是一个动作（比如"先立一个没人持有的误解再推翻"），下面列的词只是它常穿的外衣。换一套字继续做同一件事，仍然算；字面命中但句子确实在传递信息，不算。
- **看密度。** 一处修辞是作者的选择；同一段里三处，或同一个动作全文反复出现，才是毛病。

作者自己的口语词、情绪、口头禅、刻意起的名字是内容，不是毛病，不替他改正式。反过来也不为了"像人"往稿子里塞"说白了""哈哈""谁能想到"。

## 一、四个测试

拿不准一句话有没有问题，用这四个问题判断，比对词表可靠。

| 测试 | 问题 | 不通过时 |
|---|---|---|
| 搬家 | 这句话原样放进另一篇文章，还成立吗？ | 成立说明它没带本篇的信息。换成本篇独有的事实，或删掉 |
| 删除 | 删掉它，读者少知道什么？ | 什么都不少就删。少了一个事实、条件或作者的态度，就留 |
| 主语 | 谁做了什么？ | 主语是抽象名词（"工程上的现实""生态的成熟度"）时，换成人、系统或具体对象，配一个动作 |
| 朗读 | 念出来，有没有换不上气、或者日常没人这么说的地方？ | 主干提前；把不会这样用的动词换掉 |

## 二、十类动作

**1. 翻案腔。** 先替读者立一个他并没有的误解，再推翻它，给下文抬价。外衣：不是 A 而是 B；不在于 A 而在于 B；你以为 A 其实 B；看似 A 实则 B；A 不重要，重要的是 B；瓶颈从 A 转移到了 B；与其说 A 不如说 B。
改法：找到这句话真正想下的判断，从正面说出来，依据放旁边。不要换一个漂亮句式顶替。
保留：读者确实普遍持有 A，或文章用材料走完了从 A 到 B 的过程；技术上的对照、适用条件、风险边界。"不只 A，还 B"是正常递进。

> 改前：代码生成不再是瓶颈，评审才是。
> 改后：代码生成不卡人了，现在费力气的是评审。

**2. 收尾拔高。** 一段或一节把事情讲完了，末尾再补一句升华、总结、格言、展望或教条。信号：段末最后一句比别的句子短而抽象；以"这说明""可以看出""也就是说""总之"开头；能直接做成金句卡片。
改法：说完就停，停在最后一个具体事实或下一步动作上。
保留：作者借自己的经历说出的真实感受，即使听起来像结论。

> 改前：验证才是今天的关键词。
> 改后：（删。上文三件事已经各自讲了验证。）

**3. 文章谈自己。** "本文将从三个方面""接下来我们看看""写到这里""先给结论，就四句""拿一组数字看会更直观"，以及节与节之间只宣告结构的桥接句（"上面讲了 X，下面再看 Y"）。
最难认的一种用词很平常，常出现在段落交界处：给自己的材料打分（"这组数据没那么好看"），预告位置（"另一半就没这么顺了"），只给论断贴标签而不下论断（"有一个结果让事情变复杂了"），引语还没出现就先替它定性（"他说得最到位"）。
判断办法：这句话的主语是文章自己（这部分、这个故事、这组证据、这里），还是文章写的那件事？是前者就是在谈自己。
改法：直接进内容，结构交给标题和顺序。或者把评论换成它评论的那个东西：`还有一个没解决的问题是 X 能不能成立` → `只测了四十个小时，还看不出 X 能不能成立`。
保留三种：说明这一节为什么值得看的；告诉读者内容性质变了的（"前面是原则，这一节看一个真实项目"）；结尾给出具体下一步的。

**4. 抢先下判断。** 先用形容词或光杆名词给结论定性，再用冒号引出事实："逻辑很清晰：""原因很简单：""核心是：""结果：""值得注意的是"。同类的还有伪洞察词：其实、本质上、核心在于、关键在于、说白了、归根结底、更重要的是。
改法：删掉引出语，从事实起句。非留那个形容词不可，多半是后面的事实没讲清，回去补事实。

**5. 重复。** 同一段里换个说法再说一遍；同一个观点在开头、中间、结语各出现一次；同一个对象一段里换三个叫法；正文把紧邻的表格一行行念一遍；"白话："后面只是把上一句复述一遍。
改法：说一次，留信息最全的那一处。一个东西只用一个名字。正文只补表格给不了的东西：例子、判断、原因。
保留：图后面那段说明（读者靠它看懂图）。

**6. 凑整齐。** 凡列举必三项；连续三个以上同构的句子或小标题；每一节都是同一个模板（"信号 / 白话 / 判断 / 反向视角"）；"首先、其次、最后"；句子一律一样长；反过来，四五个十来字的短句连发，像打电报。
改法：有几项写几项。排比两项为限。关系紧的几点写成一段话，按内容本身的因果、转折去接。句子长短跟着内容走，不为制造变化凑字。

**7. 空话。** 意义拔高（标志着、具有重要意义、深刻影响）；商业黑话（赋能、抓手、闭环、底层逻辑、颗粒度、组合拳、降本增效）；万能判断（"门槛低，护城河在于持续迭代"）；借来的权威（"业界普遍认为""研究表明"而没有出处）；虚假范围（"从架构设计到团队文化"）；营销腔的数字（"效率翻倍""节省 37%"而不说从多少到多少）。
改法：写清谁做了什么、花了多少、后果落在谁身上。给出处，给不出就删。数字写成"从 15 万降到 2000"。

**8. 装饰。** 每个列表项以一个粗体标签开头；满屏粗体；emoji；拿引号当强调（大模型最擅长"翻译"）；破折号；多层嵌套列表；用栏目名当小标题（"竞争情报""趋势判断"）。
改法：粗体只留给读者扫读时必须找到的词，一屏两三处。引号只用于原话、系统输出和报错信息。小标题写成一句有内容的话。

**9. 聊天残留。** "希望对你有帮助""如需进一步了解""以下是……""好的，下面是"；模型自带的免责（"截至我所知""现有资料中没有广泛记载"）。
改法：全删。不知道的事，要么查清楚，要么在那句话里明说"没有查到"。

**10. 替读者定身份和反应。** "小白""普通人""你会发现""你可能会问""相信你一定……"；训人式起手（"你得先明白"）。
改法：去掉"你"做主语，直接陈述事实。

## 三、翻译腔

骨架是英文、字是中文的句子。日常没人这么说，读者每句都要在脑子里再译一遍。

| 套路 | 例子 | 改法 |
|---|---|---|
| 长定语堆在名词前 | 在经历了长达数月且始终没有稳定产出的反复调参之后，最终促使团队换掉这套方案的，是一次线上超时 | 先说谁做了什么，原因、时间、条件接在后面：这套方案调了好几个月，产出一直不稳。后来线上超时了一次，团队才把它换掉 |
| 抽象名词做主语、名词化 | 工程上的现实比这些数字难看；价值在于……；对数据进行了清洗 | 让人或具体对象做主语，用动词：这些数字只反映了采用面；最大的好处是……；清洗了数据 |
| 用物理动作写思考 | 这几条我都接住了；论证被击穿；更锋利的表述；落地；扛住 | 换成日常说法：都收到了；这个假设不成立；更准确的说法 |
| 藏起主语的被动 | 该问题已被解决；得到了显著提升 | 被动句本身不是毛病，看不出谁做的才是。写出主语：平台组上周修了这个问题；从 82% 升到 91% |
| 英文词能译不译 | context 不崩、state 可恢复 | 圈内已有通用译法的用中文（上下文、状态、缓存、运行时）；还没有稳定译法的（prompt、embedding、token）留英文 |
| 弱动词加名词 | 进行分析、作出决定、加以改进、实现了提升 | 分析、决定、改进、提升了 |
| 多余的"一个""之一""们""性" | 这是一个非常重要的问题；最常见的失败模式之一；可读性方面的问题 | 这个问题很重要；常见的失败是……；不好读 |

一句话里出现三个以上的"的"，或者读到名词时已经忘了句首，就按第一行的办法重排。复杂关系可以用长句讲完，只要主干早出现。

## 四、让句子往前走

去掉毛病只是一半。下面这些决定一段话读起来顺不顺。

- **后一句接住前一句。** 让后一句从前一句刚出现的人、物或结果说起，指向清楚时省掉重复的主语和机械连接词。两个对象同时在场、或中间隔了一大段时，把名字写回来。
- **一段说一件事。** 一段超过四百字或塞了三个不相干的概念，在概念切换处分段。单独成段的一两句话，多半是上一段的尾巴或下一段的引子，并进去。
- **具体。** 写名字、数字、动作，不写"相关方""大幅""近期"。产品和工具写真名，不写"某 AI 工具"。
- **数字带语境。** 写清口径（哪个站、哪天、什么单位）；素材里确有对照物才比较；一段里不超过三个数字，其余进表格。
- **限定词跟着证据走。** 材料支持七成就说七成，剩下的直接承认不知道。"据作者自述""未读原文""截至 2026-11"这类词承载证据强度，必须留；每句都挂"可能""或许"则是作者从文章里消失了。
- **术语。** 第一次出现时用半句话解释，或中文在前、英文括注；之后全篇只用一种写法。写作过程中自己起的简称和代号不进成稿。一段里几个术语同时首次出现时，把解释分散到各自自然出现的位置。
- **连词按作用取舍。** 中文的小句靠语序和事理就能相接。`因为店里生意不好，所以他决定把下午的时间用来学修表` → `店里生意不好，他下午闲着，就学起了修表`。真在表示转折、因果、时间的留下；按固定位置出现、拿掉不影响意思的（此外、另外、同时、与此同时、总的来说）删掉。
- **同一个词该重复就重复。** 一段里"修表"可以出现四次，不用第二次换成"这门手艺"、第三次换成"这项技能"。
- **选近的词。** 买和购买、用和使用、看和观察、改和修改，意思相近，远近不同。按说话的人和场合选，不为了显得稳重整篇换成长词。
- **说到读者能接住就停。** 动作、数字、原话已经把判断或情绪带出来时，后面不再跟一句解释。只省读者自己走得到的那一步，关键事实、因果和取舍仍然要说清。
- **比喻。** 毛病不在比喻多，在比喻不贴。汇报和文档里，原句读得懂就不用比喻；长文里可以用，但每个比喻要过三关：删掉它这段就讲不清；往深推一层仍然成立；读者不用再解释就懂。瑞士奶酪模型、飞轮这类外来模型名，读者未必知道，去掉名字直接讲道理。
- **第一人称。** "我"用来讲亲历的事和下取舍；技术判断和结论让事实做主语。素材里没有的经历、细节、对话，一个字不编。假细节越具体，机器味越重。

## 五、标题

- 标题要带判断或带问题，不只是名词：`多 Agent 协作` → `多 Agent 协作会让幻觉互相放大`。检验办法：它能不能单独成立为一句有意义的话。
- 分析、论证类用判断式；讲经历、讲探索的长文，疑问句和好奇式短语更合适（"机器人怎么知道自己在哪"）。
- 不用名词并列（"数据、算法与系统"）；不用"一、二、三"编号前缀（操作步骤除外）；副标题和主标题意思重复时并成一句。

## 六、标点和中英混排

- 生成的文字默认不用破折号（——），改用逗号、句号、冒号或括号。作者原稿里自己用的不动。
- 分号只用于对仗句和列表项之间；两句只是"感觉有关系"时用句号断开。
- 括号里超过十个字，说明它该进正文。一段里两处以上括号，至少改一处。
- 冒号用在列表和引语之前，不拿来制造"揭晓"的停顿。
- 中文和英文、数字之间留一个半角空格；中文语境用全角标点；英文专名保持原有大小写（GitHub、macOS、iOS）。
- 正文以句号结尾，列表项和表格单元格不加。

## 七、改完后的残留

每轮改完再扫一遍这五类，它们最容易漏：

1. 意思相近的词叠在一句里（"也都""也能上手用"）。
2. 超过二十五个字没有逗号的句子，朗读时想换气的地方就是该加逗号的地方。
3. 没有铺垫就出现的比喻词（"水位""账本""这条线"），以及短距离内借了三套不同的世界（道路、战争、建筑）。
4. "方案上""思路里""概念上"这类多余的方位词。
5. 一个名字第一次出现时缺了让读者区分它的修饰（谁家的、和前文那个工具什么关系）。
