# 技术公众号长文和博客

写公开发表、读者自愿来读的长文读这一份：技术公众号文章、博客、经验分享、技术解读、观点文。中英文通用。

和汇报相反，这里的读者没有义务读完，随时会走。所以除了讲清楚，还要多做两件事：让他愿意读下去，让他知道是谁在说话。这两件事都靠材料和判断，不靠修辞。

## 一、哪些必须来自作者

| 必须来自作者，助手不能代造 | 助手可以做 |
|---|---|
| 这篇文章的核心判断和切入角度 | 提三个候选主线供作者选；找支持和反对它的证据 |
| 亲历：做了什么、踩了什么坑、花了多少钱和时间 | 把作者讲的经过理顺、补上作者确认过的背景知识 |
| 态度和情绪：兴奋、后悔、不服气、没想明白 | 提结构建议，按定好的角度展开，核对事实，自查 |
| 最后的取舍：留什么、删什么、敢不敢下这个判断 | 指出哪一节缺材料、哪个判断没有依据 |
| 发出去之前亲自通读一遍 | 提醒作者这一步不能由助手代读 |

作者没给亲历，就不写亲历。说话的位置有四种：亲身做过、做过调查、熟悉这个行业、认真查完资料后形成了判断。四种都能写出好文章，但不能把后一种写成前一种。

没有亲历时这样写：只抓最有把握的一两点，不包办整个问题；有可靠的流程材料时，选一个普通角色把过程走一遍，并明说这是常见情形；一段抽象解释之后尽快落到一次报价、一行配置、一次失败。不要把原因分成六七类、每类补一个限定、结尾再总结一遍，那样句句都对，读者却碰不到任何东西。

## 二、动笔前

**1. 这个题值不值得写。** 三个问题至少答上两个：读者读完能知道一件他原来不知道的事吗？有没有一个让人想看下去的问题或反差？有没有碰到读者自己正在经历的麻烦？只答得上一个，把这个判断告诉作者，不硬写。

**2. 主线是一个判断，不是一个话题。** "聊聊 Agent 的记忆"是话题；"给 Agent 加长期记忆，先坏掉的是检索，不是存储"是判断。好的主线有人会不同意，具体到能被验证，读者在乎。说不清时用这个句式逼一下：在什么条件下，A 通过什么机制改变了 B，结果是什么。

**3. 清点材料。** 一千二百字以上的文章，先列出至少五件有来路的材料：亲历的事、数字、原话、可以核实的公开出处、一次失败。类别名不算材料，同一个意思换种说法不算第二件，读者本来就猜得到的也不算。每一节要对得上至少一件。对不上就缩短篇幅，推理可以把材料连起来，不能自己繁殖出材料。

**4. 读者是一个聪明、感兴趣、但不熟悉背景的同行。** 不是所有人，也不是学生。

**5. 选一个原型。** 它决定文章怎么往前走。

| 原型 | 读者得到什么 | 怎么推进 |
|---|---|---|
| 踩坑、排查实录 | 我替你走了一遍 | 遇到的问题 → 第一步查了什么、被哪条证据排除 → 第二步…… → 最后剩下的原因。每一步只回答一个问题 |
| 实测、体验 | 跟我一起试 | 具体场景 → 逐个试，从最平常的到最出乎意料的 → 真实感受和对比 → 判断，以及它在什么条件下成立 |
| 现象、原理解读 | 这件事背后是什么 | 现象 → 通常的解释 → 它解释不了哪一步 → 更准确的解释 → 这个解释的边界 |
| 方法、经验分享 | 我自己在用的做法 | 每一节：判断 → 例子 → 具体怎么做 → 学习成本和容易失败的地方 |
| 方案、架构复盘 | 我们为什么这样做 | 先给结果和数字 → 再讲怎么做到的 → 取舍和没走通的路 → 别人能搬走的部分 |

## 三、开头

- **从一件具体的事开始。** 那次事故、那个 bug、那个让你去查的数字、某个人说的一句话。不从定义、行业背景、"随着……的发展"开始。
- **读完前三段，读者要知道三件事：** 这篇讲什么问题，凭什么由你来讲，读下去能得到什么。用内容让他知道，不写"本文将……"。
- **技术分享可以用一张摘要卡开头：** 做了什么，最大的坑是什么，最值钱的收获是什么。五行以内。
- **可以用场景开头，但判断要在开头这一部分露面。** 读者的好奇变成困惑之前，他得知道这篇要往哪去。悬念已经交给标题了，开头不再吊胃口。
- **开头最后再改一遍。** 全文写完后，用二十秒把这篇文章讲给一个人听，再和开头对照。两者对不上时，多半是文章在写的过程中变了，按写成的文章改开头。

## 四、怎么往前走

- **每写完一段问一句：读者现在最想知道什么？** 下一段就答这个。先讲发生了什么，他会问为什么；先给判断，他会问凭什么；先讲结果，他会问中间出了什么岔子。
- **抽掉中间一节，后面还接得上吗？** 接得上，说明这几节只是并列的要点，不是一篇文章。重排，让前一节成为后一节的入口。
- **岔出去要回来，回来要多带一样东西。** 背景、例子、顺手的知识都可以岔，回来时用一句话扣回主线，并且带回一条证据、一个尺度或一个反例。出去一圈判断纹丝不动，这段只是在展示知识。
- **知识等问题走到那里再出现。** 读者问到钱再算钱，碰到那条限制再解释限制。不先把背景一次倒完。
- **一个例子用到底。** 贯穿全文的一个案例，比五个各用一次的例子省读者的力气。
- **篇幅跟着兴趣走，不求对称。** 让你意外的那一节写五倍长，铺垫性的步骤一句带过。每节一样长是机器的手笔。
- **把死胡同写出来。** 先试了什么，为什么不行。每一步都顺利、每个数据都支持论点的文章，读者不信。
- **至少下一个读者可能不同意的判断，并说出什么情况下你是错的。** "写入量在每秒一千次以下的，可以不看这一节。"几个方案各写一段却不给结论，不算分析。
- **讲机制分三步：** 先用白话说出画面，再给术语，最后给工程事实（数字、复杂度、边界）。比喻删掉后读者对机制的理解毫无损失，它就是装饰。
- **几样东西对比时逐个展示，从弱到强排。** 不要一句话把结论全交代了。
- **开头埋下的东西，结尾回来一次，回来时带上新的含义。** 只回一次。

## 五、声音

文章里始终有一个人，读者知道他站在哪里。

**人味从这些地方来：** 知识的来路（哪件事让我留意到这个问题，一开始怎么想错的，哪条材料改变了看法，哪一块到现在还没弄明白）；取舍（我为什么不选另一条路）；代价（花了多少，赔了什么）。每篇自然出现一两处就够，凑齐了又成了新模板。

**不从这些地方来：** 语气词和口头禅的数量，按篇幅分配的自嘲和吐槽，故意的不通顺，编出来的生活细节（凌晨三点、第三杯咖啡）。作者有自己的口头禅和句式时，写在风格说明里，照风格说明用。

- "我"用来讲亲历的事和下判断。不替读者说他是谁、他会怎么想。- 情绪写当时的反应，不写形容词：`我非常震撼` → `我盯着那个数看了半天`。素材里有才写。
- 姿态是同行对同行。作者原稿是"我跑过、我看到、我还没答案"的探索口气，就不要改成"我来告诉你该怎么做"的教程口气。

## 六、小标题、图和数字

- 篇幅长、读者确实需要定位时才加小标题。小标题是一个判断或一个问题，不是"背景""方案""总结"。
- 以段落为主。步骤、清单、多项对比才用列表和表格。手机上读，一段三五行，一段一件事。
- 图放在"一句引子、图、展开"的位置；图后面的说明要留；不为调节节奏凑图。
- 代码是真实跑过的片段，否则明说是示意。
- 数字带条件：什么机器、什么版本、多大数据量、跑了几次。容易过期的事实（价格、版本、界面位置）带日期。

## 七、结尾

停在这四种之一：一个具体的建议或下一步；一个你确实还没有答案的问题；回到开头那件事，带着读者现在才看得懂的含义；一个因此改变了的决定，或者付出的代价。

不停在：复述全文、升华到时代和人生、展望未来、一句可以做成卡片的话、"欢迎留言讨论"。作者素材里有他自己的感悟，原样保留；素材里没有的感悟不替他写。拿不准时，比你想停的地方早一步停。

## 八、标题

- 给四到五个候选让作者挑：两三个带钩子，一两个平铺直叙。无法询问时，用平铺直叙里最具体的那个。
- 具体胜过抽象（"150 行"胜过"一份文档"），说人话，三十个字以内，前几个字就要有信息。
- 钩子的几种来路：结果在前、具体数字、前后反差、一个读者也想问的问题、直接给解法。
- 正文必须兑现标题。不用震惊体，不用"浅谈""探索与实践"，不问没有方向的大问题。"所有人都做错了"这类翻案标题，只有正文真的用材料推翻了才用。
- 遮住正文，只看标题，一个陌生人能不能说出这篇大概讲什么？

## 九、改长稿

- **先画地图，再改句子。** 通读后列出每一节一句话在说什么，标出三类问题：同一个判断或清单在两节以上各写了一遍；正文在复述紧邻的表格；整节对主线没有贡献。不要一遍把整篇重写，那样会盖掉作者亲手调过的句子，也没法逐处核对。
- **作者自己的成稿：** 删节、合并、调顺序先提出来等确认；句子只动病句、错字和明显的机器腔；交回时附上每一处删改，作者可以逐条否决。无法询问时只做句子层的修改，结构建议写在交付说明里。
- **改完对照原稿查四样东西有没有丢：** 作者原本的反应被换成了四平八稳的抽象词；前后呼应的一组说法断了一环；带理由的句子被砍成了光秃秃的结论；具体的数字和名字被抹成了"很多""某工具"。丢了就恢复原文。更短、更克制不等于改好了。

## 十、发出去之前

1. 这篇是谁在说？
2. 他手里最硬的三样材料是什么，在文中哪里？
3. 换一个作者，能不能写出差不多的一篇？能，就是缺独有的材料或判断。这要回去找作者补，改词解决不了。
4. 从头读一遍，在哪里走了神、哪里要回头找主语？那里就是要改的地方。
5. 有没有未经授权的内部信息？有没有拿同行做反衬？
