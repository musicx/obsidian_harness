# 知识文档

写要长期留存、被人反复查的东西读这一份：概念页、操作指南、教程、参考手册、设计说明、README、新人入门文档。

知识文档的读者带着一个问题来，找到答案就走，半年后还会有另一个人带着同样的问题来。所以它要好找、能独立读懂、过了半年仍然不误导人。假想的读者是刚入组的同事，或者六个月后已经忘了细节的你自己。

## 先定这一页是哪一种

四种文档服务四种需要，写法相反，混在一页里哪一种都做不好。一页只做一种，别的需要链接到别的页。

| 类型 | 读者的状态 | 写法 | 不要做的事 |
|---|---|---|---|
| 教程 | 第一次接触，想跟着做一遍 | 带着走一条必定成功的路，每一步都能看到结果 | 讲原理、给选项、列出所有参数 |
| 操作指南 | 知道要做什么，不知道怎么做 | 标题就是任务（"如何回滚一次发布"）；前置条件 → 编号步骤 → 怎么确认成功 → 常见失败 | 从头讲概念 |
| 参考 | 干活时来查一个值 | 结构处处一致，表格为主，完整、准确、枯燥 | 夹带解释和建议 |
| 解释 | 想弄懂为什么 | 背景、设计理由、考虑过的备选、取舍；可以有观点 | 写成步骤 |

概念页属于解释，默认骨架：一句话定义 → 它解决什么问题、用在哪 → 怎么运作 → 一个真实例子 → 常见误解或边界 → 相关页面。

## 每一页都要有的

- **标题用读者会搜的词。** 写任务或对象的名字，不写"一些思考""杂记"。
- **第一段说清三件事：** 这一页回答什么问题；适用于谁、哪个版本或环境；不包括什么（并指向该去的页面）。
- **定义在使用之前。** 术语第一次出现就定义或链接到它的页面；全页、全库用同一个名字指同一个东西。在技术文档里，重复用同一个词是精确，不是啰嗦。
- **例子是真的。** 命令能直接跑，配置是实际用过的，输出是真实输出。写不出真实例子的地方，说明这部分自己还没弄清。
- **会过期的内容带时间。** 版本号、价格、界面位置、"目前不支持"这类事实，写明"截至 2026-11"或对应的版本。
- **一个事实只写在一个地方。** 别处需要时链接过去，不复制。复制的两份迟早不一致。
- **不确定和没验证的直说**，并写明缺什么。

## 指令类文字不能有两种读法

操作步骤、报错说明、配置说明里，读者会照字面执行。交稿前逐句查这几项：

| 问题 | 例子 | 改法 |
|---|---|---|
| 同一个东西换了名字 | 选择工作区……删除该项目 | 一个对象一个名字；界面上的字、参数名、路径原样照抄 |
| 不知道谁做 | worker 通知调度器之后，它会重试 | 写出是谁重试。资料里看不出来就标出待确认，不挑一个顺口的 |
| 条件和动作脱节 | "只有校验通过才重启"写成"校验通过就重启" | 前者是必要条件，后者是充分条件。条件、例外、禁止各自紧贴它管的那个动作 |
| "和""或"的范围不清 | 需要所有者或有审批的编辑者 | 说清所有者要不要审批，再写成列表 |
| 顺序丢了 | 开始上传。删除本地副本 | 上传完成之后，再删除本地副本 |
| 义务等级变了 | "建议检查"写成"检查"；"可能失败了"写成"失败了" | 必须、应该、可以；已完成、已开始、已排队；确定、可能。各是各的，改写时不能升降级 |
| 现象后面接了没有依据的原因或办法 | 连接超时。请检查密码 | 只写观察到的现象；原因和处置要有依据，并和现象分开写 |

每一步只写一个动作，并写出做完应该看到什么。真正有先后的才编号；可选的几种做法不编号。

## 交稿前

- 把这一页交给一个没有上下文的人（或一个没看过材料的模型），让他按这一页回答三个读者会问的问题。答不出或答错的地方，就是要补的地方。
- 只读标题和第一段，能不能判断这页是不是自己要找的？
- 每个命令、路径、数字都对照来源核过一遍。
- 全页有没有同一个东西的两种叫法？
