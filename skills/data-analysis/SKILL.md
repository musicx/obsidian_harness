# 回答数据问题

**完成的标准：** 用户的问题得到了直接的回答，或得到了"数据答不了"的明确说明；结论里的每个数字都出自贴在笔记里的查询；口径和局限写清楚了。

**边界：** 只写 `analysis/`（属于某个项目的写 `projects/<项目>/analysis/`）和 `datasets/`。只查 `_brief.md` 里列出的数据源。只做取数和描述性分析：不做预测，不给买卖建议，不评价策略好坏。

## 步骤

1. **弄清问题。** 读线程页和 `_brief.md`。把问题拆成三样：要算什么指标、对谁算（标的、范围）、在什么时间上算。有两种合理的理解时，按更可能的那种做，并在笔记开头写明你的理解。

2. **找表。** 先读 `datasets/_index.md` 和相关的数据字典页。字典里没有的，用 `list_tables` 看有哪些表，用 `describe_table` 看候选表的字段、行数和时间范围。同一类数据有多张表时（不同来源、是否复权、不同周期），在笔记的"方法与口径"里写明为什么选这一张。

3. **先小后大。** 每张要用的表先跑一条探查查询：最新日期是哪天、一个标的一天有几行、关键字段有没有空值。发现与预期不符（重复行、单位不对、日期缺口）时，先解决或绕开，并记下来。

4. **写正式查询。** 聚合在 SQL 里完成，结果控制在几十行以内。分位数、排名、同比环比用窗口函数或聚合函数算，不要把明细拉回来自己算。

5. **核对。** 用另一种写法或一个已知的事实交叉验证关键数字（比如抽一个标的手工核对，或换一张来源不同的表比一下量级）。对不上就查原因，查不出来就在"局限"里如实写。

6. **写分析笔记**（格式见下）。答案一两句话能说清、且只用了一条查询时，可以不建笔记，直接把结论、数据截至日期和那条查询写进 `_report.md`。

7. **更新数据字典。** 这次用到的表：字典里没有页面的，建一页；已有页面但你发现了新的坑或更好的用法，更新它。格式见 `_skill/references/dataset-page.md`。

8. 对照 `_skills/writing/SKILL.md` 第 6 步（体裁参考读 `_skills/writing/references/report.md`）和下面的清单自查。

## 分析笔记的格式

`analysis/YYYY-MM-DD <标题>.md`

    ---
    type: analysis
    question: 用户的问题
    source: <数据源名>
    as_of: YYYY-MM-DD          # 数据截至日期，取自查询结果里的最新日期
    date: YYYY-MM-DD
    ---
    # <标题：直接说出结论>

    一两句结论，带数据截至日期。

    ## 方法与口径
    用了哪些表、时间范围、样本怎么筛的、复权和单位、怎么处理停牌和缺失。

    ## 结果
    表格。需要看趋势或对比时配一张 Mermaid 图。

    ## 查询
    每条正式查询一个 sql 代码块，原样粘贴你执行过的那一条。

    ## 局限
    数据截止、覆盖范围、口径上的取舍、没能验证的地方。

- 表格里的数字保留合理的位数，带单位；比例写百分数。
- 链接数据字典页：`[[datasets/<数据源>/<表名>|<表名>]]`。
- 探查用的查询不用贴，只贴得出结论所用的查询。
- **贴出的 SQL 必须与执行的一字不差。** 想整理格式，就先把整理好的那一版执行一遍，再粘贴。

## 检查清单

- [ ] 第一句就是结论，带数据截至日期
- [ ] 结论和表格里的每个数字都能在某条贴出的查询的结果里找到
- [ ] 每个 sql 代码块都是原样执行过的
- [ ] `as_of` 来自查询结果，不是今天的日期
- [ ] 口径写清了：表、时间范围、复权、单位、样本
- [ ] 用到的每张表在 `datasets/` 里都有页面

## 容易出错的地方

| 发生过的事 | 规则 |
|---|---|
| 把成交量的"手"当成"股"，结果差了一百倍 | 用到带单位的字段前，看字典或用一个已知标的核对量级 |
| 日线表里同一天同一标的有两行，求和翻倍 | 第 3 步先数一遍每个主键有几行；有重复就在查询里去重并写进局限 |
| 用未复权价格算了跨除权日的收益率 | 算收益用后复权或前复权的表，并写明是哪一种 |
| 只看了还在上市的标的，结论偏乐观 | 样本是否包含已退市标的，写进口径；做不到就写进局限 |
| 问"现在"，用的却是表里已经停更的数据 | 先查最新日期；距今超过几个交易日就在结论里明说 |
| 笔记里的 SQL 是整理过格式的，和执行的那条不完全一样 | 整理后重新执行，再粘贴 |
| 修改一篇已有的分析笔记时，保留了上次的查询却没有重跑 | 用户提修改意见时新建一个带 ` v2` 的文件，里面保留的每条查询都重新执行一遍；数据可能已经更新，结论要跟着新结果走 |

## 报告

`_report.md` 的摘要不超过 300 字，用普通段落：结论和数据截至日期；用了哪个数据源的哪些表；最重要的一条局限。数据答不了时写明缺什么。
