# 记录我们的做法

**完成的标准：** `_brief.md` 的"可写范围"指定的那个 `practice/….md` 已写好，里面的每一句都能在用户的话里找到对应；含糊之处已在报告里列出。

**边界：** 只能写"可写范围"里指定的那一个 `practice/` 文件。没有指定时不要写，报告 `status: blocked`。

## 步骤

1. 读线程页里用户写的话。那就是全部素材。
2. 查 `_context/names.md`：`practice/` 里是否已有讲同一件事的文档。
   - 已有，且"可写范围"指定的正是它：把新说的内容融进去，用户这次的说法与文档原有内容冲突时，以这次为准，并在报告里指出改了哪里。
   - 已有，但指定的是另一个新文件名：不要另建一份重复的。报告 `status: blocked`，说明已有哪篇文档，请用户确认是更新它还是确实要分成两篇。
3. 把用户的话整理成文档：
   - 可以调整顺序、合并重复、把口语理顺、加小标题；
   - **不可以**补充步骤、原则、理由、数字或例子——即使它们是常识，即使文档因此显得单薄；
   - 用户说得笼统的地方（"一般""几次""差不多"）照原样保留。
4. 写 frontmatter：`type: practice`、`owner: human`、`description`（这篇讲我们怎么做什么）、`aliases`、`updated`。

## 文档格式

    ---
    type: practice
    owner: human
    description: 我们目前如何……；做……之前先读
    aliases: []
    updated: YYYY-MM-DD
    ---
    # <做法的名字>

    正文：用列表或短段落，一条一个做法。

## 检查清单

- [ ] 逐句核对：每一句都对应用户的某句话，没有多出来的内容
- [ ] 没有把笼统的说法改成具体的（"几次"没有变成"三次"）
- [ ] 没有加入评价（"这种做法的问题在于……"）

## 容易出错的地方

| 发生过的事 | 规则 |
|---|---|
| 用户说"回测用全部历史数据调参"，文档里多了一句"并做样本外验证" | 用户没说的不写。觉得缺了什么，写进报告里的"待确认"，不写进文档 |
| 把用户的做法改写成了"最佳实践"的语气 | 记录现状，不是写规范。用"我们目前……" |

## 报告

摘要不超过 200 字：文档记了哪几点；然后是"待确认"——用户的话里含糊、可能被误解的地方，逐条列出，请他补充。不要替他回答。
