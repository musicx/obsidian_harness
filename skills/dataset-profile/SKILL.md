# 摸清一张表

**完成的标准：** 每张目标表在 `datasets/<数据源>/` 下有一页，写的内容都经过查询确认；以后做分析的人读了这一页，就知道这张表能不能用、怎么用、要避开什么。

**边界：** 只写 `datasets/`。只查 `_brief.md` 里列出的数据源。一次任务最多梳理 6 张表；用户要的范围更大时，先做最重要的 6 张，其余在报告里列出。

## 步骤

1. 读线程页和 `_brief.md`，确定目标表。用户说的是一类数据而不是表名时，用 `list_tables` 找出相关的表，按相关程度和行数选出要梳理的。
2. 对每张表：
   1. `describe_table` 看字段、行数、排序键和时间范围。
   2. **粒度**：按你猜测的主键分组，数一数有没有重复（`count()` 与 `uniqExact` 对比，或找出行数大于 1 的分组）。
   3. **覆盖**：最早和最新的日期；最近一个交易日有多少行；按年看行数有没有断层。
   4. **关键字段**：对分析常用的数值字段，看取值范围和空值比例；用一个你有把握的标的或日期核对量级，确认单位。
   5. **与相近表的区别**：有同类表时（不同来源、是否复权、不同周期），抽同一标的同一天各查一行，比较差异。
3. 按 `_skill/references/dataset-page.md` 的格式写页面。已有页面就更新，不要另建。
4. 每张表的探查查询控制在十条以内。查不出来的事不要猜，写"（未确认）"。

`_skill/references/dataset-page.md` 是页面格式，动笔前先读。

## 检查清单

- [ ] 粒度是查出来的，不是从表名猜的
- [ ] 时间范围和最新日期来自查询结果
- [ ] 单位用已知标的核对过，或标了"（未确认）"
- [ ] 页面里的 sql 代码块都原样执行过
- [ ] `description` 说清了"什么时候该用这张表"

## 容易出错的地方

| 发生过的事 | 规则 |
|---|---|
| 表名带 `daily` 就写"每个标的每天一行"，实际有重复 | 粒度一定要数 |
| 对几亿行的表做全表去重计数，查询超时 | 先限定一个月或一批标的；需要全表的统计用 `describe_table` 给的行数 |
| 把所有字段都列进了"关键字段" | 只列做分析会用到的，其余读者可以自己看表结构 |

## 报告

`_report.md` 摘要不超过 300 字：梳理了哪几张表；每张表一句话说它是什么、能不能放心用；最值得注意的坑；还有哪些相关的表没有梳理。
