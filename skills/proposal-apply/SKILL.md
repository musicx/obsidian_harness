# 落实被采纳的建议

**完成的标准：** 目标文件里，被采纳的每一条都已按建议落笔并注明依据；未被采纳的内容与原文逐字相同；建议页的状态和处理结果已更新。

**边界：** 你只能修改 `_brief.md` 的"可写范围"里列出的那一个 `practice/….md` 文件，以及 `proposals/` 和 `wiki/`。"可写范围"里没有 `practice/` 文件时，说明没有获得授权：不要动任何我方文档，在报告里说明并把 `status` 设为 `blocked`。

## 步骤

1. 读线程页，确定用户采纳了哪几条：
   - "采纳""都采纳""可以"＝全部；
   - "采纳 1、3"＝只有这两条；"第 2 条不要"＝除第 2 条外全部；
   - 用户对某条提了修改意见（"第 3 条改成上限 15%"）＝按他的说法落实那一条。
   - 读不出明确的采纳范围：不要猜，`_report.md` 的 `status` 设为 `blocked`，在摘要里问清楚。
2. 读建议页和目标文件的全文。
3. 逐条落实。每改一处：
   - 只替换建议里指明的句子，或只在指明的位置增加内容；
   - 在被改动或新增的句子后注明：`（依据 [[来源摘要页]]，YYYY-MM-DD 采纳）`；
   - 保持文档原有的结构、语气和格式。
4. 目标文件不存在（被采纳的是一份初稿）：按建议页里的初稿新建，frontmatter 用规范里"我方文档"的格式，去掉"这是初稿"的提示语。
5. 更新目标文件 frontmatter 的 `updated`。
6. 更新建议页：`status` 改为 `accepted`（全部采纳）或 `partially-accepted`；在文末加：

       ## 处理结果
       - 第 1 条：已采纳并落实。
       - 第 2 条：未采纳。
       - 第 3 条：按用户意见调整后落实（上限改为 15%）。

## 检查清单

- [ ] 改动只落在被采纳的条目上；逐句对比过，其余内容没有变化（包括标点和空行）
- [ ] 每处改动后都有依据和采纳日期
- [ ] 建议页的 `status` 与"处理结果"一致
- [ ] 目标文件仍有 `type: practice`、`owner: human`、`description`

## 容易出错的地方

| 发生过的事 | 规则 |
|---|---|
| 顺手把相邻的句子也"润色"了 | 不在建议里的字一个都不改 |
| 采纳了第 1、2 条，却把第 3 条的修改也带上了，因为它们在同一段 | 按条目落实，不按段落 |
| 把建议里的示例文字原样贴进去，和上下文语气不搭 | 意思照建议，措辞可以贴合文档原有的写法，但不能改变建议的内容 |

## 报告

摘要不超过 200 字：落实了哪几条、目标文件现在的变化要点、未采纳的条目。
