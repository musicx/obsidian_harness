# 整理知识库

知识库是一篇篇材料陆续收录进来的，时间长了会出现重复的页面、没人链接的页面、挂了很久的分歧。这次任务是做一遍清理。

**完成的标准：** `_context/health.md` 里的每一项都有了结论：已处理，或写明为什么不处理、需要用户决定什么。没有留下任何指向已删除页面的链接。

**边界：** 只写 `wiki/`。不改 `raw/`、`practice/`、`projects/`。只整理已有内容，不从记忆里补充新知识。

## 步骤

先完整读 `_context/health.md`，再按下面的顺序处理。每一类处理完再做下一类。

### 1. 名称相近的页面

对每一对，把两页都读完，给出三种结论之一：

- **合并**：讲的是同一个东西（同一概念的不同叫法、单复数、中英文名）。
- **保留**：名字像但内容不同（Server Actions / Server Components），或一个是另一个的子话题且各自内容充实。给两页互加链接，并在各自的 `description` 里写清区别。
- **拿不准**：不动，列进报告让用户决定。

合并的做法：

1. 选内容更完整、被链接更多的一页作为保留页。
2. 把另一页的内容逐段融进保留页的相应位置，出处一并带过去；两页说法不一致的地方用 `[!conflict]` 并列。
3. 保留页的 `sources` 取两页的并集，`aliases` 加上被合并页的名字和别名，`topics` 取并集。
4. 用 grep 在整个 `wiki/` 里找出所有链接到被合并页的地方，逐个改成保留页的名字（保留原来的显示文字）。来源页 frontmatter 的 `concepts` 也要改。
5. 删除被合并页。
6. 再 grep 一次被合并页的名字，确认没有残留的链接。

### 2. 可升格的概念

被两个以上来源提到、但还没有页面的概念：读那几个来源页（必要时读它们的原文相关段落），内容够写成一页就新建概念页，并从这些来源页的 `mentions` 里移除它、加进 `concepts`。几个来源都只是一句带过、凑不出实质内容的，保持不动。

### 3. 孤儿页

没有任何页面链接到的概念页或实体页：在它的来源页和主题相近的页面里，找到提及它的地方加上链接。确实与其他内容无关的，保持不动并列进报告。

### 4. 缺少描述的页面

读正文，补一句 `description`："这里有什么；什么时候该读"。顺带检查同一页的其他必填项：来源页缺 `raw` 时，从正文开头指向原文的链接里取出原文目录补上；概念和实体页缺 `sources` 时，从正文的出处链接里补。

### 5. 带分歧标记的页面

读 `[!conflict]` 里的各方说法和它们的来源页。知识库里已经有了能分出对错或新旧的依据时，改写为确定的说法，并把 `[!conflict]` 换成 `[!outdated]` 记录原说法。没有新依据的，保持不动。

### 6. 长期未更新的页面

只检查，不改写：内容里有"目前""最新""今年"这类会过期的说法时，列进报告。

## 检查清单

- [ ] 每次合并后都 grep 确认没有指向被删页面的链接
- [ ] 合并没有丢内容：被合并页的每一段都能在保留页里找到
- [ ] 没有因为名字相似就合并内容不同的页面
- [ ] 没有为了消除"孤儿"而硬加不相干的链接
- [ ] health.md 的每一项在报告里都有交代

## 容易出错的地方

| 发生过的事 | 规则 |
|---|---|
| 批量替换链接时把显示文字也换掉了，句子读不通 | 只换链接目标，保留 `\|` 后面的显示文字；没有显示文字的补上原来的名字作显示文字 |
| 合并时把两页的内容首尾相接 | 逐段融合，同一要点只留一处 |
| 为了让数字好看，一次删改了几十页 | 拿不准的不动。少做一项没有损失，做错一项很难发现 |

## 报告

摘要不超过 400 字，按类别写：合并了哪几对（保留页 ← 被合并页）、升格了哪些概念、补了哪些链接和描述、解决了哪些分歧；然后是"需要你决定"——拿不准的页面对、可能过期的内容，各一行。
